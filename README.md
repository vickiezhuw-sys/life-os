- 先恢复 Weekly Planner 的结构、文案和主要交互；

- 基线稳定后，再开发 `Build = 内容 + 日期 + 时间`；
- Build 后续增加日 / 周 / 月 / 年统计。

## Build v1

Build 已加入主工程，但保留 Weekly Planner 作为独立视图。

当前能力：
- 快速记录内容
- 日期 + 时间
- 浏览器本地持久化
- 日 / 周 / 月 / 年筛选统计
- 记录数 / 活跃天数 / 全部累计
- 删除记录

数据仍保存在当前浏览器的 `localStorage`，下一阶段可迁移到云端存储。

记录时可以填写投入时长（分钟）；Build 页面按日、周、月、年展示累计时长柱状图。升级前已有的记录继续保留，但因为没有时长字段，会显示“未记录时长”。
每条记录可选择五个 Life OS 模块之一。统计区可以切换“全部 OS”或单个模块，记录列表与时长图表会同步筛选；旧记录可通过“编辑”补上模块和时长。

Weekly Planner 打开时默认显示设备本地日期所在的周（周一至周日），旧任务和勾选状态保留。2026-09-21 至 09-27 周补充了旅行记录、身体照顾与周复盘任务；这些任务只会加入一次，后续每周可自行添加计划。
2026 年 9 月剩余日期及整个 10 月的计划放在 `src/sep-oct-plan.json`：旅行、离职交接、简历与 AI 数据学习、求职、财务核对和生活复盘按天安排。升级时只追加一次，用户后续的勾选、编辑和删除不会被覆盖。

## Project 35 · 对话驱动执行维护协议（2026-10-11）

- Life OS 是任务执行与完成状态的操作系统；AI × Wealth OS Google Doc 是长期目标、财务现状及决策的事实源。
- 用户通过自然语言向 AI 汇报执行进度；AI 负责核对对应任务，并在可访问的 GitHub / 云端能力范围内维护计划、进度和纠偏。
- **严禁将 GitHub 模板数据更新误报为用户浏览器或 Supabase 中任务已勾选。** 实际勾选状态存于浏览器 localStorage 或 Supabase 用户快照。未取得对应写入能力时，明确标记为「已收到完成反馈，尚未同步线上状态」。
- 状态规则：未开始 / 进行中 / 已完成 / 延期 / 阻塞；每次进度记录包含汇报日期、实际结果、证据或反馈来源、下一步。
- 已完成任务以用户的实际完成反馈为准；不因为预定截止日到达而自动勾选。
- 每月复盘检查执行进度和结果（财务安全、求职转化、AI 交付、第二收入），没有达到要求时提出纠偏和下月前三优先任务。
- 对旧任务、同名任务做语义匹配去重，优先保留已完成状态和备注；重大调整保留变更记录。

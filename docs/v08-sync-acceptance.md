# V0.8 同步安全补充验收

2026-10-27：PR #3/#4 仍为 Draft，main 未包含它们。本补丁基于 #3；不直接发布。

## 本次修复

- 重命名、移动任务时记录旧语义标识的删除标记；删除另存 UUID 标记，防止旧版本复活。
- 历史简历迁移不再覆盖带 updatedAt 的用户显式修改。
- 删除时间以真实时间戳比较，兼容带时区的旧备份。
- 云写入使用现有 updated_at 做条件更新；并发写入失败后重新拉取合并，最多三次。首次插入竞争不会覆盖已有行。不需要修改数据库结构。
- Windows CRLF 测试加载兼容；所有目标分支 PR 运行质量检查；Pages 构建使用 Node 22、锁文件安装，并先运行测试。

## 验收步骤

1. 两台设备先导出 JSON 备份，记录任务数、已完成数及 Build 时长。
2. A 修改任务名称/日期，B 保留旧副本后同步；确认旧任务不复活。删除后再用旧备份合并检查。
3. 对历史简历任务取消完成、重新加载和同步，确认用户操作保留。
4. 两台运行本补丁的设备同时修改不同任务并同步；确认双方任务均保留，失败能显示并重试。
5. 断网编辑、恢复网络后手动同步；确认本地记录未丢失。
6. 导出再导入备份，核对上述数据；回归 Day、Weekly、Month、Build、Agents。

## 发布限制

用户已确认旧版跨设备验收完成；这不能替代新条件写入协议在真实 Supabase 上的验收。
自动测试用模拟 HTTP 验证条件写入、插入竞争及失败，未连接用户生产数据。
旧页面仍使用无条件写入；发布后所有设备必须刷新，旧客户端仍可能覆盖云端。
同一任务两个设备同时修改的完整冲突历史/选择界面仍未实现；现有时间戳决策受设备时钟影响。
Build 记录仍沿用既有按 ID 合并策略，跨设备编辑同一条记录需要后续版本化。
以上风险未验收前，维持 Draft，不合并 main。

# Life OS V1.0 RC1 · 验收说明

## 版本范围

V1.0 候选版完成基础执行闭环，不代表正式发布。基于 PR #6（含 V0.8/V0.9 补丁），保留 Day / Weekly / Month / Build / Agents / Sync。

- 「目标与计划」：长期目标包含可验证的成果标准和期限；项目关联目标、记录下一个里程碑。支持修改与归档/恢复，不删除历史关联。
- 月成果计划、周成果计划可关联；月计划汇总子周计划的任务。可直接拆成每日任务，保留 projectId / planId，改名或改期后关联继续存在。
- Day 快速捕获进入收集箱；用户选择日期和项目后安排为任务。重复安排不会新建重复任务；两设备独立安排同一捕获使用同一个任务 ID。
- Build 可关联任务和项目，仍由用户填写真实内容、时间和时长，不自动补时或完成。
- 「周月复盘」可选择历史周期，汇总实际任务完成率、Build 分钟及计划成果，填写实际成果、阻塞和下一步。下一步可明确加入收集箱并安排到日期。
- 投入按 Build 开始日期归属，累计记录时长；不宣称是去除重叠后的净投入。任务完成率不等于长期目标达成率，里程碑成果由用户自行验证。

## 数据兼容

- 保留原快照 version:1 与原 localStorage 键，只增添 lifecycleVersion 和 goals/projects/plans/captures/periodReviews 集合。历史无关联任务仍可使用，不自动归类或生成目标。
- 第一次从已有数据升级时保存一份升级前快照，可在 Sync 导出；不保存登录凭据。导入前额外保存恢复快照，拒绝明显格式不兼容的文件。
- 新集合按稳定 ID 和 updatedAt 合并，归档作为版本化状态保留；较新清空字段不会被旧文本覆盖。
- 统一生产代码和测试使用的任务合并模块，显式改名/改期依据稳定 ID 合并；保留旧版语义去重兼容。
- Build 修改带时间戳，删除记录带 tombstone，避免旧设备或旧备份复活已删除记录。

## 手工验收（发布前）

1. Sync 导出当前备份和升级前备份，记录任务、完成数、Build 时长。
2. 建立一个真实目标和项目，添加月周成果计划并拆任务；修改标题和日期，检查所有来源关联。
3. 为实际执行填写 Build，关联任务/项目；核对日、周、月统计。不要为了验收填写虚假投入。
4. 填写周复盘，下一步加入收集箱并安排；重复操作应不重复创建。月复盘重复上述过程。
5. 重载、导出/导入备份，核对目标到任务的关联、复盘和旧记录。
6. 两台运行新版的设备进行真实 Supabase 并发操作、断网重试、归档、笔记清空及 Build 删除验收。
7. 真机手机检查 375/390/768px 常见布局、键盘输入、日期选择、长标题、任务编辑和备份导入。

## 发布门禁与限制

- RC1 提交独立分支和 Draft PR；未合并 main，未部署正式站。依赖分支需按 #3/#5/#4/#6/V1.0 的实际内容统一后再合并。
- 真实 Supabase 新协议与真机手机验收仍待执行；本地模拟并发测试不能替代它们。
- 同一字段在多设备同时改动仍按时间戳选择，设备时钟偏差、完整冲突历史与用户选择界面尚未完成。旧客户端仍可无条件写入云端，发布后必须刷新所有设备。
- 首次升级备份保存在当前浏览器，仍应导出到独立存储。没有数据库迁移或生产数据写入。
- 暂不包含 AI 教练、Agent 编排、外部工具集成，维持已确认排期。
